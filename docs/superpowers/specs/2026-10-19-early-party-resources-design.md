## Design

This is an architectural change to shared evidence ownership. Extending the old delayed warning would retain discovery-gated missing contributions. Broadcasting current inventory would lose consumed grants and misclassify pickups. Instead, keep one run-owned absolute starting-contribution ledger, separate from current inventory, floor source evidence, population, and local reminders.

The exact server `HOTSPOT! Your Hunting Hotspot is the <Biome> Biome!` message starts a once-only +2,000 ms schedule. Island arrival, entry banners, polling and area changes do not. The existing run object owns the schedule; replacement/disconnect cancels it. Sample grant inventory on early tracking ticks and synchronously at entry/grant/hotspot events. Preserve observed quantities after use; Head Start is a one-item lower bound overlapping the silent First Class inventory grant. Keep grant sampling open through initial post-HOTSPOT updates, closing before the first resource interaction/pickup or the two-second deadline, subtract positively observed floor pickups, and never infer an unobserved silent grant. A missing first snapshot is unknown, not an empty report.

One report contains all applicable food/coins, independently of mode/discovery/HUD/ESP. Canonical order: coin, seeds, worm, berry. Explicit `none` distinguishes received zero from a missing report. Reports are absolute sender/type quantities; local witness, echo, repeat and legacy maxima overlap. Consumption cannot reduce demand. A current roster UUID is the sender key. Unknown roster/missing reports remain unknown.

Accept only anchored real party envelopes on GAME/CHAT after verifying sender UUID against the current roster. Bind queued identity work to the receiving run/world/connection and recheck on completion. Scope new reports to a witnessed reward-display UUID in the current run: the sender includes a short marker token, and the receiver admits it only after observing that same marker identity. This provides shared provenance without assuming local run UUIDs are shared. If marker context is unavailable, keep the report pending/unknown and do not invent another player's inventory. Legacy notices and bare completion words retain their unavoidable lack of on-wire run identity; admit live current-run party messages only, never replay stored chat, and document the limitation.

Reuse the Safari-wide reward acquisition. A dedicated source catalog retains one validated STRING triple per group, its actual pickup evidence and coverage separately from visibility. Structural coverage requires the complete documented phase prefix (six Cavern gem groups, nine Forest food groups, five Haunted incense groups, a closed Haunted phase followed by the five Icy groups), contiguous IDs within each phase and no unresolved prefix gaps/partial markers. Derive F from observed coin groups, never a three-coin constant. A missing/partial initial catalog stays unknown. This is structural support for the existing order classifier, not a new server reward field; live typing remains a documented limitation. Marker disappearance alone neither collects a slot nor lowers F. Verified current zero remaining resources plus sufficient fresh spawning population can resolve sources without falsely declaring a disappearance to be a pickup.

Bird demand is the verified nine-food baseline/observed slots plus the common starting-food total, with existing Macaw equivalents, scan circle, held/remaining blockers, six separate personal pickup events and capture rules. Ordinary pickups do not become starting extras based on the player's biome. Retained proof/report targets must cover current demand; new demand reopens applicable completion announcements.

Gimmiegold keeps its existing F+S versus C+U owner. Normalize known aliases and exclude known resolved models before counting current U; do not accumulate historical UUIDs or manufacture captures. Require known source/report coverage, no current held/remaining blockers and a qualified fresh C+U proof. Outside Haunted, a current demand-stamped hd can supply remote spawning proof without local renders; inside Haunted local evidence controls. New slots/contributions/report coverage invalidate older report stamps. Unique/Full Clear continue to require actual captures.

The later end-of-clearing reminder keeps its discovery, destination, quantity and delay rules, with one combined readable title/subtitle. Its delivery only marks presentation state. Remove all automatic unused-item local/party chat sends. Normal completion words and unrelated commands remain unchanged.
